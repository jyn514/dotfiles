# Check rule scope before asking about precedence

Use this check when a proposed human decision depends on an apparent conflict between rules or categories.

Read the surrounding explanation, related requirements, and examples before declaring a contradiction.
Check directly documented behavior before inventing explanations or case-specific exceptions; an apparent omission may be explained elsewhere.
Separate explicit statements from your reconstruction because a plausible explanation is not source authority.

Trace category provenance.
A label may come from an authoritative source while its application to a particular case comes from an unreviewed agent assessment.
Identify both origins, and state the uncertainty if the requirement's applicability depends on that assessment.

Identify each rule's applicable unit, such as a word, syllable, stroke, record, or batch.
Check whether someone applied a rule outside that unit or the implementation crossed its boundary.
Do not ask a human to resolve an unexamined scope assumption.

Before asking which rule takes precedence, use contrasting cases to check whether both rules apply to the same situation.
For example, *b* is silent in *thumb*, but starts the second syllable in *stumble*.
The same written letters do not necessarily make the same rule applicable.
Resolve applicability first; ask about precedence only if it remains unresolved.
